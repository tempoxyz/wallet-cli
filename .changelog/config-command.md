---
wallet-cli: minor
---

Added `tempo wallet config get [key]`, `config set <key> <value>`, and `config unset <key>`, which save `network`, `rpc-url`, and `max-spend` in `~/.tempo/wallet/config.json`, readable only by you. A command's flag, then the setting's environment variable (`TEMPO_WALLET_NETWORK`, `TEMPO_RPC_URL`, or `TEMPO_MAX_SPEND`), still beats the saved value, which beats the built-in default. `config get` reports each setting's effective `value` and its `source` (`flag`, `env`, `config`, `login`, or `default`), showing `rpc-url` redacted as `doctor` does. An unknown key fails with `E_USAGE` listing the valid ones, and a config file that is not valid fails the commands that read it with `E_USAGE` naming the file; `doctor` reports it instead. Each command, or MCP tool call, reads the config file once, so it uses one set of settings throughout, and a change saved meanwhile applies to the next command.

A saved `network` also beats the logged-in wallet's network, as `TEMPO_WALLET_NETWORK` does, so commands stay on it after a `login --network` elsewhere until you pass `--network` or change the setting. It does not narrow `keys list` or `logout`, which still cover every network unless `--network` or `TEMPO_WALLET_NETWORK` selects one. A saved `rpc-url` is one endpoint for every network, like `TEMPO_RPC_URL`. With either set, `whoami`, `keys list`, and `balance` now count a balance, a key's on-chain state, or an unlisted token's metadata only once the endpoint's `eth_chainId` matches the network, and report it as unknown otherwise, never another chain's value. A saved `max-spend` must be positive and counts as an explicit cap, like `TEMPO_MAX_SPEND`: it allows MACH payments and refuses subscription offers.

Since these settings decide what later payments and RPC calls use, `config set` and `config unset` need confirmation, as `transfer` does: in a terminal they show the setting's value before and after and ask, and agent, MCP, or piped runs change nothing without `--yes`, failing with `E_USAGE` and a `cta` that adds it. An `rpc-url` whose path, query, or user info can carry a credential appears in that `cta` as `<rpc-url>`, to be replaced with the full URL. Setting `rpc-url` also warns that the endpoint will receive all of the CLI's RPC traffic. Saving the value already saved, or removing a setting that is not saved, needs no confirmation. Without `--yes`, a change applies only while the setting still holds the value it was confirmed against: if another process changed it meanwhile, nothing changes and the command fails with a retryable `E_USAGE`. Over MCP, `config_get` is read-only, and `config_set` and `config_unset` are destructive and idempotent.
