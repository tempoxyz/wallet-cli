`tempo wallet transfer` token transfers and `tempo wallet swap` accept `--idempotency-key <key>`, so a retried send cannot go out twice. Each key is recorded for the logged-in wallet on the resolved network in `~/.tempo/wallet/idempotency/` (mode 0600) before the transaction is sent, and pruned after 30 days. Rerunning a key that sent the same request sends nothing and returns the recorded result with `idempotent_replay: true` and `status` read from the chain; a key used for a different request fails with `E_USAGE` naming the arguments that differ; and a key whose send never recorded an outcome fails with `E_PAYMENT_OUTCOME_UNKNOWN` instead of sending again. Dry runs record nothing and carry the key into `_next`. `E_PAYMENT_OUTCOME_UNKNOWN` from `transfer` and `swap` is now returned with a `cta`: with a known transaction hash, the message names it and the `cta` is `tempo wallet tx status <hash> --network <network>`; otherwise the `cta` is `tempo wallet whoami`. The new `tempo wallet tx status <hash>` (MCP `tx_status`, read-only) reports a transaction's `status` (`success`, `reverted`, `pending`, or `not_found`), `block_number`, `from`, `to`, and `fee`, each RPC read bounded to five seconds, with a `_next` that polls a pending transaction.
