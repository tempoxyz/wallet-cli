Accept token symbols listed by viem for the selected network (case-insensitive, e.g. `USDC.e`, `usdc`, `pathUSD`, `MACH`) wherever a token is taken: `tempo wallet swap`, `tempo wallet transfer`, `--fee-token`, `tempo wallet keys update --token`, and `tempo request --payment-token`. Unknown symbols fail with `E_USAGE` and list the network's symbols; `tempo request` rejects a `--payment-token` symbol that no network lists before sending the request. Token addresses are accepted in any case, and `_next` continuations carry the resolved address. `keys update --limit` is read in the token's own decimals and rejects extra precision, so a swap whose input token is not 6-decimal now also points a limited key at `keys update`. `whoami` and `keys` show symbols from the same listing (now `pathUSD`, `OUSD`, `MACH`) and spending limits in each token's decimals, with the stored base units in a new `raw_limit` field. Unlisted tokens are read on chain once per token, and only for the active wallet's keys; when a token's symbol or decimals are unknown, `symbol` and `limit` are `null` rather than an address or a guessed scale. An unlisted token's on-chain or asset-list symbol is shown only when it is a plain ticker (up to 16 letters, digits, `.`, `_`, or `-`); otherwise its `symbol` is `null`, including in `swap` and `transfer` output, and instructions and errors name it by its address. `sessions` reports listed symbols or `null`.
